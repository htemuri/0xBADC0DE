## Run as daemon

In order to persist my emacs sessions between different client processes, I start up an Emacs daemon on boot through `systemd`. My system unit file looks like below and is stored in `/etc/systemd/system/emacs.service`:

```ini
[Unit]
Description=Emacs Daemon
Documentation=man:emacs(1)

[Service]
Type=simple
ExecStart=/usr/bin/emacs --fg-daemon
ExecStop=/usr/bin/emacsclient --eval "(kill-emacs)"
Restart=on-failure

[Install]
Wanted=default.target
```

After creating this service unit file, if you're running a RHEL distribution with SELinux enabled, you have to reevaluate the security context for the file with the following command:

```bash
sudo /sbin/restorecon -v /etc/systemd/system/emacs.service
```

Then you should be able to start and enable the service

```bash
sudo systemctl start emacs
sudo systemctl enable emacs
```

<Callout>If you're scoping the emacs daemon service for the user, then you should throw the file in `/etc/systemd/user/emacs.service` and add the `--user` flag to the `systemctl` commands above.</Callout>

## Client Desktop App

I'm running on GNOME desktop with dark mode, and because Emacs is still running on legacy gtk, you have to set the theme manually with an environment variable when starting the Emacs client[^1]. I updated the Emacs desktop app configuration (in `/usr/share/applications/emacs.desktop`) to the following:

```ini
[Desktop Entry]
Name=Emacs
GenericName=Text Editor
Comment=Edit text
MimeType=text/english;text/plain;text/x-makefile;text/x-c++hdr;text/x-c++src;text/x-chdr;text/x-csrc;text/x-java;text/x-moc;text/x-pascal;text/x-tcl;text/x-tex;application/x-shellscript;text/x-c;text/x-c++;
Exec=env GTK_THEME=Adwaita:dark emacs %F
Icon=emacs
Type=Application
Terminal=false
Categories=Development;TextEditor;
StartupNotify=true
```
